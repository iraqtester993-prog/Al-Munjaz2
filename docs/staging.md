# البيئة التجريبية ببيانات حقيقية

## النطاقات

- `staging-app.our-qiq.com`: تطبيق التاجر والمندوب التجريبي.
- `staging-dashboard.our-qiq.com`: لوحة الإدارة التجريبية.
- `staging-api.our-qiq.com`: API التجريبي.

## القاعدة الصحيحة

التجريبي لا يتصل أبداً بقاعدة إنتاج `ourqiq_almunjaz`. أنشئ قاعدة مستقلة باسم مثل `ourqiq_almunjaz_staging`، ثم انسخ إليها نسخة من بيانات الإنتاج في وقت محدد. وبذلك تظهر بيانات حقيقية عند النسخ، لكن أي إضافة أو حذف أو اختبار يبقى داخل التجريبي.

لا تستخدم حساب MySQL الإنتاج في التجريبي، ولا تضع اسم قاعدة الإنتاج في ملف `.env` التجريبي.

## دورة التحديث

1. خذ نسخة احتياطية من قاعدة الإنتاج.
2. استوردها إلى قاعدة Staging المستقلة.
3. عيّن في `backend/.env` للتجريبي متغيرات `.env.staging.example`.
4. عطّل البريد الفعلي والخدمات الخارجية؛ استخدم `MAIL_MAILER=log`.
5. انشر نسخة Git المراد اختبارها إلى نطاقات Staging.
6. اختبر الميزات والتعديلات.
7. بعد الموافقة، انشر نفس commit على الإنتاج.

## حماية البيانات

صلاحية Staging تكون للمدير والفريق فقط، مع كلمة مرور إضافية على النطاق إن أمكن. لا تشارك رابط التجريبي أو قاعدة بياناته علناً، ولا تسمح بإرسال رسائل أو عمليات مالية فعلية منه.

## لماذا لا نربطه مباشرة بالإنتاج؟

يمكن أن يغيّر الاختبار طلبات أو أرصدة أو مستخدمين حقيقيين. النسخة المستقلة تقدم بيانات واقعية للمشاهدة واختبار الميزات، وتفصل تأثيرها تماماً عن العملاء.
